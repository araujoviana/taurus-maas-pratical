## What this project is

A live demo environment for **TaurusDB (Huawei Cloud GaussDB for MySQL)** integrated with **MaaS AI (GLM-5.1)** in a fintech scenario. Built for a ~20-minute enterprise presentation. Three acts:

- **Act 1 — Performance Storm**: Bulk-load 500k transactions; show live QPS/latency on the dashboard
- **Act 2 — HA Resilience**: Trigger a TaurusDB primary→standby switchover via Huawei Cloud API; show <30s recovery through the proxy
- **Act 3 — MaaS AI Integration**: GLM-5.1 fraud analysis against live fintech data

The dashboard (FastAPI + WebSocket) runs on port 8000 on a public ECS, protected by nginx basic auth. The presenter opens a browser — no local port-forwarding needed.

## Commands

```bash
# Install dependencies locally
uv sync

# Run tests (all)
uv run pytest tests/ -v

# Run a single test file
uv run pytest tests/test_collectors.py -v

# Local dev server (no infra needed — DB unavailable, but app starts)
uv run python main.py

# Provision ALL infrastructure and deploy app (Terraform + Ansible)
make up

# Seed the database manually (after make up)
make seed

# Stream app logs from ECS
make logs

# Tear down all infrastructure
make down
```

`make up` runs three steps: `terraform apply`, then `scripts/gen_inventory.py` (bridges TF outputs → `ansible/inventory.ini` + `.env`), then `ansible-playbook`.

## Architecture

### Metrics pipeline

`TaurusDBCollector.collect()` runs `SHOW GLOBAL STATUS LIKE '…'` (threads_connected, queries, slow_queries) + one `SELECT 1` latency probe via aiomysql. QPS is computed as a **delta rate**: `(queries_now - queries_prev) / elapsed_seconds`. Raw cumulative counter is stored in `_prev_queries`.

`MAASCollector.collect()` pings GLM-5.1 with a 1-token prompt to measure round-trip latency. It caches the result for 30 seconds (`MAAS_REFRESH_INTERVAL`) so the 1-second WebSocket tick does not hammer the LLM API.

The `/ws` WebSocket endpoint calls both collectors on every tick (MaaS returns cached) and pushes a JSON payload to all connected browsers.

### Scenario control

The browser POSTs to `/scenario/start-load`, `/scenario/kill-primary`, `/scenario/ai-analyze`, or `/scenario/reset`. `ScenarioManager` is an async state machine; blocking I/O (bulk insert, HW Cloud REST, AI call) runs via `run_in_executor`. Scenarios lazily import from `scenarios/` so the package is never loaded at startup.

### Failover mechanism (Act 2)

`scenarios/failover.py` calls `POST /v3/{project_id}/instances/{instance_id}/failover/switchover` on `gaussdb-mysql.{region}.myhuaweicloud.com` with AKSK signing via `huaweicloudsdkcore`. After the API call succeeds, it polls `SELECT 1` until TaurusDB accepts connections again (max 120s). The TaurusDB proxy keeps the endpoint address stable — clients see only a brief QPS dip.

### Auth

`/auth/login` issues a JWT (HS256, 8h TTL). The secret is `DEMO_PASSWORD` from `.env`. `auth_dependency(secret)` is a FastAPI Depends factory used on protected routes.

### AI fraud analysis (Act 3)

`scenarios/ai_analytics.py` pulls the 20 most recent flagged transactions + 30 random samples, builds a structured prompt, and calls GLM-5.1 via `openai.OpenAI(base_url=MAAS_BASE_URL, api_key=MAAS_API_KEY)`. Returns analysis text + token usage. High-risk accounts (risk_score ≥ 7) are escalated to risk_score=10 in the database.

## Environment variables

See `.env.example` for the full list. Variables auto-filled by `gen_inventory.py` after `terraform apply`: `TAURUS_HOST`, `TAURUS_PORT`, `TAURUS_INSTANCE_ID`, `DEMO_RUNNER_IP`. You must supply before `make up`: `HW_ACCESS_KEY`, `HW_SECRET_KEY`, `HW_PROJECT_ID`, `SSH_KEY_PATH`.

`DEMO_PASSWORD` is used for: TaurusDB user password, nginx `auth_basic` htpasswd (username: `admin`), and as the JWT secret seed.

## Key implementation details

- **QPS metric**: Uses delta from `SHOW GLOBAL STATUS LIKE 'Queries'` (cumulative counter). First call always returns 0.0 QPS; subsequent calls compute the rate.
- **MaaS cache**: `MAASCollector._last_check` and `_cached` prevent LLM calls on every WebSocket tick. Cache expires after `MAAS_REFRESH_INTERVAL = 30.0` seconds.
- **Workload seeding**: `scenarios/workload.py` seeds 200 accounts + 10k transactions inline (called from `ScenarioManager.start_load`). `scripts/seed_data.py` is a separate CLI for full 10k accounts + 500k transaction seeding (run once after deploy).
- **Failover**: Requires `TAURUS_INSTANCE_ID` in `.env` (auto-filled by `gen_inventory.py`). Without it, `run_failover()` raises a descriptive `RuntimeError`.
- **DB pool**: `TaurusDB` uses `minsize=2, maxsize=10`. `autocommit=True` so individual queries do not need explicit commits.
